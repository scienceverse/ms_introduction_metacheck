# Description
This repository accompanies the paper introducing **Metacheck**, a modular tool for assessing the presence (or absence) of best research practices in scientific manuscripts. As a demonstration, we apply **Metacheck** to a sample of articles published in Psychological Science.
All analyes can be found in the `manuscript.qmd`.

# Repository structure

```text
metacheck_paper/
├── input/                            # Data used in the analyses
│   ├── psychsci.rds                  # Articles used to run the Metacheck modules
│   ├── psych_science_crossref.RData  # Crossref metadata for the articles
│   ├── res_stat_p_exact.RData        # Results of the `stat_p_exact` module 
│   ├── res_stat_effect_size.RData    # Results of the `stat_effect_size` module 
│   ├── res_power.RData               # Results of the `power` module using the rule-based approach
│   ├── res_power_llm.RData           # Results of the `power` module using the LLM-based approach
│   └── res_open_practices.RData      # Results of the `open_practices` module
├── manuscript.qmd                    # Quarto manuscript source file
├── manuscript.html                   # Rendered HTML manuscript
├── manuscript.docx                   # Rendered DOCX manuscript
├── bibliography_doi.bib              # Bibliography file containing references
├── output/                           # Generated outputs (figures, tables, and rendered files)
├── _extensions/                      # Quarto extensions used by the manuscript
├── apa.csl                           # APA citation style file
└── session-info.txt                  # # R session information
```

# Data and Code

The files in the `/input` folder contain `.rds` and `RData` files generated by running code, but often require:
- internet access
- access to an LLM
- hours to run

To make the analyses easier to reproduce, we ran the data modules once and stored the resulting files in the `input/` folder. However, these data files may not be fully reproducible if the online resources used to create them change over time. For example:
- Authors can close projects on the OSF, making them inaccessible
- Authors can open projects, making them accessible
- OpenAlex might update their database with new information
